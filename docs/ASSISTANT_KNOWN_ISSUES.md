## 1. 流式输出体验不稳定，部分回答仍可能大段输出

- 发现阶段：第一阶段稳定性与边界优化。
- 风险等级：中。
- 影响范围：用户体验。
- 是否影响主流程正确性：暂未发现。
- 是否阻塞下一阶段：不阻塞。
- 是否立即修复：否，进入待办问题池。
- 当前结论：暂不在当前阶段继续扩大流式改造范围；最小评测问题集已生成，下一步先执行回归并记录失败项。

### 问题表现

- 固定话术虽然走 NDJSON `delta`，但因为没有节流，可能被快速塞入队列并一次性输出。
- 上游 LLM 即使使用 `stream=true`，也可能返回较大的 delta。
- 后端目前没有对 delta 统一做二次切分和节流。
- 部分业务分支仍是内部完整生成后，再由外层输出。
- 前端收到 `delta` 后已立即 append，前端不是主要问题。
- 主要风险点在后端 delta 产生节奏、queue drain 逻辑或上游代理缓冲。

### 已确认现状

- 固定话术已支持通过 NDJSON `delta` 输出。
- LLM 总结已初步接入 OpenAI-compatible `/chat/completions stream=true`。
- 前端已按 `delta` 事件逐步追加文本。
- 流式体验仍可能不稳定，尤其是固定话术、缓存命中、完整业务结果外层输出和上游模型大 delta 场景。

### 后续可选方案

1. 在 `main.py` 输出包装层统一做 delta 二次切分。
2. 增加轻微节流，让固定话术和大 delta 有可感知输出节奏。
3. 增加 no-buffering headers，降低代理或浏览器缓冲影响。
4. 逐步补齐 `push_preview`、`warning_handle`、`warning_trend`、`teacher_risk`、`classroom_health`、`device_ops` 等分支内部 streaming。
5. 增加 streaming smoke 测试，验证 `meta -> delta* -> done` 的输出顺序、分片数量和时间间隔。

### 暂缓原因

- 当前问题主要影响体验，暂未发现影响业务回答正确性。
- 继续扩大流式改造会触碰 `main.py` 输出包装层和更多业务分支，容易扩大回归面。
- 下一步更适合先执行 `docs/ASSISTANT_EVAL_CASES.md` 中的 64 条评测问题并记录失败项，再决定具体实现方案。
