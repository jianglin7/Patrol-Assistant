# Codex 工作流提示词模板

本文档用于后续在 `xunke` 小助手项目中使用 Codex 时，快速发起阶段任务选择、单任务开发、代码 Review 和任务状态更新。

使用前请先让 Codex 阅读：

- `AGENTS.md`
- `docs/ASSISTANT_ROADMAP.md`
- 与当前任务相关的代码和 Markdown 文档

通用限制：

- 不读取或输出 `.env`、密钥、token、数据库密码、API Key、完整数据库连接串。
- 不执行数据库写操作。
- 不执行删除、部署、重启、清库等高风险命令。
- 不修改 `offline_bundle/`、大 SQL dump、zip、tar、Docker 镜像文件，除非明确要求。
- 不改变已有接口 URL、请求参数和响应结构，除非明确评审并确认。
- 涉及 SQL 时必须检查参数化、租户隔离、逻辑删除字段和只读保护。

## 1. 阶段任务选择模板

适用场景：准备进入一个新阶段或新迭代时，让 Codex 基于路线图和真实代码选择最适合落地的任务。

```text
你现在位于 xunke 小助手项目根目录。

请阅读：

- AGENTS.md
- docs/ASSISTANT_ROADMAP.md
- 当前已有能力边界、任务拆解、项目分析类 Markdown 文档
- 与小助手相关的核心代码：
  - query_service/app/main.py
  - query_service/app/patrol_api.py
  - query_service/app/service.py
  - query_service/app/semantic_planner.py
  - query_service/app/semantic_executor.py
  - query_service/app/semantic_report.py
  - query_service/resources/assistant_semantic/

本轮只做分析，不修改任何文件。

请从 docs/ASSISTANT_ROADMAP.md 中选择一个最适合作为当前阶段落地的任务。

任务选择原则：

1. 优先影响稳定性、安全性或用户体验的问题。
2. 修改范围尽量小。
3. 不需要改数据库结构。
4. 不需要大范围重构。
5. 不需要新增大型依赖。
6. 可以通过手工问题集或最小验证清单验收。
7. 对现有接口兼容性影响小。

请输出：

1. 推荐任务名称。
2. 为什么优先做这个任务。
3. 当前代码现状。
4. 预计修改范围。
5. 具体实现方案。
6. 验收问题集或验证方式。
7. 风险点。
8. 回滚方式。
9. 下一轮可直接执行开发的提示词。

严格限制：

- 不修改任何文件。
- 不读取或输出敏感信息。
- 不执行数据库写操作。
- 不执行部署、重启、删除等高风险命令。
- 所有结论必须基于当前项目真实代码；无法确认的内容写“待确认”。
```

## 2. 单任务开发模板

适用场景：已经确定一个小任务，需要 Codex 按最小范围完成开发、验证和总结。

```text
你现在位于 xunke 小助手项目根目录。

请先阅读：

- AGENTS.md
- docs/ASSISTANT_ROADMAP.md
- 与本任务相关的代码和文档

本轮任务：

【任务名称】
在这里写清楚本次要落地的单个任务，例如：
小助手问题边界识别与模糊问题追问兜底。

【目标效果】
在这里写清楚期望效果，例如：
当用户问题缺少业务域、时间范围、对象角色或排行维度时，小助手先追问；当用户请求读取密钥、修改数据、跨租户查询或绕过权限时，小助手明确拒绝或提示权限边界。

【允许修改范围】
只允许修改以下文件：

- query_service/app/patrol_api.py

如确实需要修改其他文件，请先说明原因并停止，等我确认。

【禁止事项】

1. 不修改数据库结构。
2. 不修改 .env、配置文件、依赖文件、SQL dump、zip、tar、Docker 镜像文件。
3. 不修改 offline_bundle/。
4. 不改变现有接口 URL、请求参数和响应结构。
5. 不新增大型依赖。
6. 不执行数据库写操作。
7. 不执行部署、重启、删除等高风险命令。
8. 不输出密钥、token、数据库密码、API Key、完整数据库连接串。

【实现要求】

1. 修改前先阅读相关函数，说明准备改哪里。
2. 尽量复用现有代码结构和函数。
3. 保持现有问答链路兼容。
4. 保留原有兜底逻辑。
5. 涉及 trace 时不得记录敏感信息。
6. 涉及 SQL 时必须保持参数化、租户隔离和只读保护。
7. 修改后提供最小验证方式。

【验收问题或验证命令】

请至少覆盖以下类型：

- 明确巡课问题
- 明确预警问题
- 模糊问题
- 缺少时间范围
- 缺少对象
- 指标解释
- 不支持问题
- 安全边界问题

完成后请输出：

1. 修改了哪些文件。
2. 为什么这样改。
3. 影响哪些接口或功能。
4. 如何验证。
5. 验证结果。
6. 是否存在待确认风险。
```

## 3. Review 模板

适用场景：某轮代码或文档已修改完成，需要 Codex 只做审查，不继续改代码。

```text
你现在位于 xunke 小助手项目根目录。

请 review 本轮改动，不要继续改代码。

请先阅读：

- AGENTS.md
- docs/ASSISTANT_ROADMAP.md
- 本轮改动涉及的文件

请重点检查：

1. 是否违反 AGENTS.md。
2. 是否扩大了修改范围。
3. 是否修改了业务代码以外的文件。
4. 是否改变了已有接口 URL、请求参数或响应结构。
5. 是否存在敏感信息输出风险。
6. 是否存在跨租户查询风险。
7. 是否存在 SQL 注入风险。
8. SQL 是否保持参数化。
9. 是否遗漏 tenant_id / tenant_org_code 租户隔离条件。
10. 是否遗漏 recycle_sign / delete_flag 等逻辑删除过滤条件。
11. 是否影响已有巡课指标口径。
12. 是否影响已有预警指标口径。
13. 是否影响 assistant 流式 NDJSON 返回约定。
14. 是否影响 LLM 失败兜底逻辑。
15. 是否有未处理异常。
16. trace 或日志是否可能输出密钥、token、数据库密码、API Key、完整连接串。
17. 是否需要更新 docs/ASSISTANT_ROADMAP.md 或其他任务状态文档。
18. 是否有清晰验证方式。
19. 是否有可回滚方式。
20. 是否存在需要业务、后端、DBA 或数据人员确认的问题。

请输出 review 结果，结构如下：

1. 结论：通过 / 有问题需修复 / 待确认。
2. 发现的问题：按严重程度排序，带文件和行号。
3. 风险说明。
4. 建议修复方式。
5. 需要补充的验证。
6. 需要人工确认的问题。

严格限制：

- 本轮只 review，不修改任何文件。
- 不读取或输出敏感信息。
- 不执行数据库写操作。
- 不执行部署、重启、删除等高风险命令。
```

## 4. 任务状态更新模板

```text
请基于当前代码、AGENTS.md、docs/ASSISTANT_ROADMAP.md 和本轮已完成任务，更新任务状态文档。

本轮只允许新增或更新以下 Markdown 文档：

- docs/ASSISTANT_ROADMAP.md

如需要更新其他 Markdown 文档，请先说明原因并停止，等我确认。

请更新内容包括：

1. 本轮完成了哪个任务。
2. 任务属于哪个 Phase 和哪个优先级。
3. 修改了哪些文件。
4. 影响哪些接口或功能。
5. 已完成哪些验证。
6. 还有哪些待确认问题。
7. 后续推荐做哪个任务。
8. 是否需要业务、后端、DBA 或数据人员确认。

严格限制：

1. 不修改业务代码。
2. 不修改 .env、配置文件、依赖文件、SQL dump、zip、tar、Docker 镜像文件。
3. 不修改 offline_bundle/。
4. 不读取或输出密钥、token、数据库密码、API Key、完整数据库连接串。
5. 不执行数据库写操作。
6. 不执行部署、重启、删除等高风险命令。

完成后请输出：

1. 更新了哪个文档。
2. 更新了哪些状态。
3. 主要依据是什么。
4. 下一步建议。
```

## 5. 推荐使用顺序

建议按以下顺序使用这些模板：

1. 阶段任务选择模板：先选一个小而稳的任务。
2. 单任务开发模板：只落地一个任务，控制修改范围。
3. Review 模板：开发后先审查，不急着继续扩展。
4. 任务状态更新模板：确认通过后再同步路线图或任务状态。

如果任务涉及数据库、SQL、租户隔离、生产配置、部署、重启、删除文件或推送到真实消息渠道，必须先让 Codex 停下来说明风险，并由用户明确确认后再继续。
